# คู่มือทดสอบบัญชีลูกค้า — Customer Login Test Guide

วิธีทดสอบระบบบัญชีลูกค้า (สมัคร / เข้าสู่ระบบ / โปรไฟล์ / ราคาตามระดับ) พร้อม
**บัญชีทดสอบสำเร็จรูป** สำหรับทั้งฝั่งลูกค้าและฝั่งแอดมิน ใช้ได้ทั้งเว็บจริง
(https://nong-kati.vercel.app) และเครื่อง local

> **ฝั่งแอดมิน:** ดูรายละเอียดเต็มที่ `docs/admin-login-test.md` —

## 1. บัญชีทดสอบลูกค้า

สร้างผ่าน DB แล้ว (ต่างจากบัญชีแอดมินที่ seed อัตโนมัติ — บัญชีลูกค้า
ต้องรันสคริปต์ หรือสมัครเองผ่านหน้าเว็บ):

| อีเมล                    | รหัสผ่าน      | ระดับราคา (tier) | เงินในกระเป๋า | ไว้ทดสอบอะไร                                          |
| ------------------------ | ------------- | ---------------- | ------------- | ----------------------------------------------------- |
| `qa-customer@test.local` | `customer123` | retail (ปกติ)    | ฿36.20        | เข้าสู่ระบบ, โปรไฟล์, popover เครดิต, ซื้อแบบราคาปกติ |
| `qa-member@test.local`   | `customer123` | member (สมาชิก)  | ฿0            | **ราคาสมาชิก** — เห็นราคาถูกกว่าหน้าร้านปกติ          |

หากต้องการบัญชีตัวแทน (dealer) ให้สมัครใหม่ผ่านหน้าเว็บ แล้วให้แอดมินตั้ง
tier = dealer ในหน้า ลูกค้า (หรือแจ้ง dev รันสคริปต์ seed)

### เส้นทางที่ใช้ทดสอบ

- หน้าเข้าสู่ระบบ: `/account/login`
- หน้าสมัคร: `/account/register` (สมัครแล้วเข้าสู่ระบบอัตโนมัติ)
- ภาพรวมโปรไฟล์: `/account/overview` — เครดิตคงเหลือ / ค่าใช้จ่ายเดือนนี้ /
  เติมเงินเดือนนี้ / ยอดใช้จ่ายสะสม / ประวัติการเติมเงิน
- รายการโปรด: `/account/wishlist` · คำสั่งซื้อ: `/account/orders`
- คำสั่งซื้อโดยไม่ล็อกอิน: `/orders/lookup` (อีเมล + เลขคำสั่งซื้อ)

### พฤติกรรมเซสชันลูกค้า (สำคัญสำหรับ QA)

- ล็อกอินเก็บใน **cookie httpOnly** (`nk_session`) — JS อ่านไม่ได้ (ปลอดภัย
  จาก XSS) ถ้าจะเช็คสถานะให้ดูที่ API `/api/v1/auth/me`
- ติ๊ก **จดจำฉัน** ตอนล็อกอิน → อยู่ได้ **30 วัน**
- ไม่ติ๊ก → อยู่ได้ **15 นาที** (ออกแบบไว้สำหรับเครื่องส่วนรวม)
- รหัสผ่านผิด 5 ครั้ง → บัญชีล็อก 15 นาที (ปลดได้จากหน้าลูกค้าในแอดมิน)

## 2. ทดสอบราคาตามระดับ (tier pricing) — เคสหลัก

1. เปิดหน้าสินค้าใดก็ได้แบบ **ไม่ล็อกอิน** → จดราคา (ราคาปลีก)
2. ล็อกอินด้วย `qa-member@test.local` / `customer123` → เปิดสินค้าเดิม
   → ราคาต้อง**ถูกลง** (memberPrice)
3. ใส่ตะกร้า → ไปหน้าชำระเงิน → ยอดรวมต้องตรงกับราคาที่เห็น
   (ราคาทุกระดับ **รวม VAT 7% แล้ว** — ห้ามบวกซ้ำ)
4. สั่งซื้อจริง → เลขออเดอร์เกิดขึ้น → แอดมินเห็นราคา tier เดียวกันในหน้าคำสั่งซื้อ
5. ลบสินค้าในตะกร้าทิ้งหลังทดสอบ

## 5. หมายเหตุสำหรับ dev

- บัญชี `qa-customer` / `qa-member` มีอยู่จริงใน DB ทุก environment ที่ชี้
  Supabase เดียวกัน (production รวมอยู่) — ปลอดภัยเพราะรหัสผ่านอ่อนแต่
  สิทธิ์เป็นแค่ลูกค้าทั่วไป **ก่อนเปิดใช้จริงกับลูกค้าปลายทาง ให้ลบทิ้ง**
  (`DELETE FROM "Customer" WHERE email LIKE 'qa-%@test.local';`)
- บัญชีแอดมิน seed ตัวเองเมื่อมีคนยิง login API ครั้งแรก (`ensureSeedAdmin`)
  — รหัสผ่าน override ได้ด้วย env `ADMIN_SEED_PASSWORD` ฯลฯ
- Implementation: `src/api/customerAuth.ts` (scrypt + JWT ใน cookie),
  `src/api/adminAuth.ts` (scrypt + TOTP + refresh rotation)
