## 1. เข้าสู่ระบบแอดมิน

1. เปิดหน้า **`/management/login`**
2. กรอก **อีเมล + รหัสผ่าน**
3. กด **เข้าสู่ระบบ** → ระบบจะถาม **รหัส 6 หลัก** จากแอป Authenticator (Google Authenticator / Authy)
4. เปิดแอป Authenticator → ดูโค้ด 6 หลักของ "Nong-Kati Admin" → พิมพ์ลงช่อง → กด **ยืนยัน**

### บัญชีที่มีในระบบ

| อีเมล | สิทธิ์ | ใช้ทำอะไร |
|---|---|---|
| `admin@nong-kati.co.th` | ผู้ดูแลสูงสุด | ทุกอย่าง |
| `catalogue@nong-kati.co.th` | ผู้จัดการสินค้า | สินค้า/หมวดหมู่/คลัง (เปลี่ยนรหัสผ่านครั้งแรก) |
| `orders@nong-kati.co.th` | ผู้จัดการคำสั่งซื้อ | คำสั่งซื้อ/ลูกค้า/รีวิว (เปลี่ยนรหัสผ่านครั้งแรก) |

> 🔐 **เคล็ดลับ TOTP:** โค้ด 6 หลักเปลี่ยนทุก **30 วินาที** ถ้าพิมพ์ช้าหรือหมดเวลาพอดี
> ระบบจะขึ้น "รหัสไม่ถูกต้อง" — ไม่ต้องตกใจ รอโค้ดใหม่แล้ว**เริ่มขั้นตอนเข้าสู่ระบบใหม่ทั้งหมด**
> (พิมพ์รหัสผ่านใหม่ → ยืนยันด้วยโค้ดใหม่ทันที) ใช้เวลาไม่เกิน 15 วินาที
>
> ติ๊ก **"จดจำการเข้าสู่ระบบไว้ในเครื่องนี้ (30 วัน)"** เพื่อไม่ต้องยืนยัน 2FA บ่อย (เครื่องส่วนตัวเท่านั้น)

ลืมรหัสผ่าน/หลุด Authenticator → ให้ super_admin อีกคนปลดล็อก/รีเซ็ตให้ ที่ **เจ้าหน้าที่** (หน้า Staff)

## 2. เตรียมข้อมูลทดสอบด้วยปุ่มเดียว (Dev only)

> ⚠️ ใช้ได้เฉพาะบนเว็บทดสอบ (localhost / preview) — **บนเว็บจริง (production) ปุ่มนี้ไม่มี**

ไปที่ **`/management/dev-seed`** → กดปุ่ม **🧪 สร้างข้อมูลทดสอบ** หนึ่งครั้ง ระบบจะสร้าง:

- ลูกค้าทดสอบ พร้อม **เครดิต ฿100** (อีเมลแสดงบนหน้าจอทันที เช่น `seed-test-1790...@test.local`)
- **โค้ดทดสอบ 2 ชิ้น** ในสินค้าราคาถูกที่สุด (รูปแบบสั้น `seed…:test1234`)

กดซ้ำได้เรื่อย ๆ ระบบจะเติมให้พอดี ไม่ซ้ำ

ขั้นตอนต่อไปเพื่อทดสอบแบบครบวงจร:
1. ตั้งรหัสผ่านให้ลูกค้าทดสอบ (แจ้งโปรแกรมเมอร์ หรือสมัครบัญชีใหม่แล้วปรับเครดิตเองแทน)
2. ล็อกอินเป็นลูกค้า → ซื้อสินค้านั้นด้วยเครดิต → โค้ดจะขึ้นทันที (ดู §5)

## 3. เติมสต๊อกโค้ด (จัดการสต๊อก)

สินค้าของเราคือ **โค้ด/บัญชี** — ต้องเติมโค้ดก่อนถึงจะขายได้

1. **สินค้า** → หาแถวสินค้า → กดปุ่ม **จัดการสต๊อก** (ไอคอนรูปกุญแจ)
   - ใช้ได้ที่หน้า **คลังสินค้า** เช่นกัน (ช่องค้นหาพิมพ์ชื่อสินค้าหรือ Type ID ได้)
2. เลือก **รูปแบบข้อมูล:**
   - **แบบสั้น (user:pass)** — บัญชีทั่วไป หนึ่งบรรทัดต่อหนึ่งโค้ด เช่น
     ```
     user01:pass1111
     user02:pass2222
     ```
     เลือกตัวคั่นได้: Comma / Semicolon / Tab (ถ้าข้อมูลเป็น `user,pass`)
   - **แบบยาว (ข้อมูลหลายบรรทัด)** — บัญชีที่มีข้อความยาว/อีโมจิ เช่น บล็อก HBO
     - **บรรทัดว่าง 2 บรรทัดติดกัน = แยกบัญชี** (บรรทัดว่าง 1 บรรทัดภายในบล็อกเดียวกันจะถูกเก็บไว้)
     - ข้อความทั้งหมดในบล็อกจะส่งถึงลูกค้าตรงตามต้นฉบับ
3. วางข้อมูลลงช่องใหญ่ → กด **แยกข้อมูล**
4. ตรวจตัวอย่าง **ไอดี #1, #2, …** ให้ตรงกับจำนวนที่ต้องการ ("จำนวนไอดีที่จะสร้าง: N")
5. กด **บันทึก** — จบ

### สิ่งที่ระบบทำให้อัตโนมัติหลังบันทึก

- โค้ดถูก **เข้ารหัส** ก่อนเก็บ (คนอื่นดูข้อมูลดิบไม่ได้)
- จำนวน **สต๊อก +N** ทันที และบันทึกประวัติ **StockMove (restock)**
- วางไฟล์เดิมซ้ำ → ระบบ **ข้ามโค้ดที่ซ้ำอัตโนมัติ** ไม่ error

> 💡 แบ่งโค้ดหลายสินค้า: สินค้าที่มีหลายแพ็กเกจ (variants) ระบบจะแจกโค้ดเข้าแพ็กเกจแบบวนรอบ
> ใช้บรรทัดขึ้นต้นด้วย `Label:` เพื่อระบุแพ็กเกจเฉพาะได้

## 4. เพิ่มเครดิตให้ลูกค้า

1. **ลูกค้า** → ค้นหาอีเมลลูกค้า → กด **ดู**
2. ในกล่อง **เครดิต/เงินในกระเป๋า** จะเห็นยอดปัจจุบัน
3. ใส่จำนวน:
   - `100` = เพิ่ม ฿100
   - `-50` = หัก ฿50 (ระบบจะถามยืนยัน)
4. ใส่ **หมายเหตุ** เช่น "โอนเงินเข้าธนาคาร 22/9" → กด **ปรับเครดิต**

ระบบบันทึกรายการใน **ประวัติการเติมเงินของลูกค้า** ให้อัตโนมัติ (แสดงเป็น "แอดมินปรับเครดิต")
ลูกค้าเห็นยอดทันทีที่หน้า **บัญชี → กระเป๋าเงิน**

> ⚠️ หักเกินยอดไม่ได้ — ระบบปฏิเสธและยอดเดิมไม่ถูกแตะ
> ในตาราง **ลูกค้า** คอลัมน์ **เครดิตคงเหลือ** แสดงยอดทุกคน (สีเขียว = มีเครดิต)

---

## 5. โค้ดถึงมือลูกค้าได้ 3 ทาง

**ทางที่ 1 — เครดิต (ทันทีที่สุด):** ลูกค้าเลือก "เครดิตในกระเป๋า" ตอนชำระเงิน → ระบบหักเงิน + ส่งโค้ดในหน้าเดียวจบ

**ทางที่ 2 — PromptPay (อัตโนมัติ):** ลูกค้าสแกน QR → ธนาคารแจ้งระบบอัตโนมัติ → โค้ดถูกส่งภายในไม่กี่วินาที (แอดมินไม่ต้องทำอะไร)

**ทางที่ 3 — สลิปแมนนวล (แอดมินกดยืนยัน):** ดู §6

**ลูกค้าดูโค้ดได้ 3 จุด:**
1. หน้ายืนยันการชำระเงิน (ทันทีที่จ่ายเสร็จ)
2. **บัญชี → โค้ดของฉัน** (`/account/codes`) — เก็บทุกโค้ดที่เคยซื้อ
3. หน้ารายละเอียดคำสั่งซื้อของตัวเอง

> หากลูกค้าบอกว่า "ยังไม่ได้รับโค้ด" → ให้ดูสถานะออเดอร์ที่ §6 ก่อนเสมอ

## 6. ยืนยันสลิปแมนนวล (คำสั่งซื้อ)

ใช้เมื่อลูกค้า **โอนเงินแล้วแต่ระบบยังไม่จับได้** (โอนผ่านธนาคารที่ไม่ webhook ทันที / ส่งสลิปมาใน LINE)

1. **คำสั่งซื้อ** → หาออเดอร์สถานะ **รอชำระเงิน** (ตรวจสลิปกับยอดและเวลา)
2. กด **ยืนยันการชำระเงิน** หนึ่งครั้ง — ระบบจะ:
   - เปลี่ยนสถานะเป็น **สำเร็จ**
   - **ส่งโค้ดให้ลูกค้าทันที** (ตัดสต๊อก + บันทึกประวัติให้เอง)
3. ถ้าขึ้น **รอจัดส่งด้วยตนเอง (manual fulfilment)** = โค้ดไม่พอตอนนั้น
   → เติมโค้ดก่อน (§3) → กลับมากดยืนยัน/ลองใหม่ → ระบบส่งให้เอง

> 🔒 กดซ้ำไม่ได้ — ออเดอร์จ่ายแล้วจะถูกล็อก ไม่มีทางส่งโค้ดซ้ำ
> ทุกการยืนยันถูกบันทึกว่าใครกดเมื่อไร (audit log)

## 7. เครดิตไม่พอเกิดอะไรขึ้น

ทดสอบแล้ว 3 สถานการณ์:

| สถานการณ์ | ที่ลูกค้าเห็น | ผลระบบ |
|---|---|---|
| เครดิต ฿0 | ตัวเลือกเครดิต**หายไปเอง** เหลือ PromptPay | ไม่มีอะไรพัง |
| เครดิตน้อยกว่าราคา | "ยอดเครดิตไม่พอ — เลือกชำระผ่าน PromptPay แทนได้เลย" | ยอดไม่ถูกหัก ออเดอร์ยังจ่ายได้ |
| ระบบขัดข้องชั่วคราว | "ระบบเครดิตขัดข้องชั่วคราว" → **เด้งไป QR PromptPay ให้เอง** | ลูกค้ายังซื้อต่อได้ ไม่ต้องเริ่มใหม่ |

**ไม่มีทางเกิด "เงินถูกหักแต่ไม่ได้โค้ด"** — ระบบหักเงิน+ส่งโค้ดเป็นชุดเดียว ถ้าขั้นไหนล้มเหลวทุกอย่างย้อนกลับอัตโนมัติ

## 8. เคล็ดลับการใช้งานจริง

**การเติมสต๊อก**
- เติมโค้ดก่อนโฆษณาสินค้าเสมอ — สินค้าที่สต๊อก 0 ขึ้น "หมด" และปิดปุ่มซื้อทันที
- คัดลอกจากไฟล์ Excel/Notion วางตรง ๆ ได้ ไม่ต้องแก้รูปแบบ
- สต๊อกใกล้หมด → ระบบแจ้งเตือนใน **Discord** ตั้งค่าได้ที่ **ตั้งค่า**

**ราคาและส่วนลด**
- แก้ราคาทีละช่องได้เลยในตารางสินค้า (ต้นทุน/ราคา/สมาชิก/ตัวแทน/สต๊อก) — แก้แล้วกด Enter บันทึกทันที
- ราคา **สมาชิก/ตัวแทน** ใช้กับลูกค้าที่ตั้งระดับไว้ (ลูกค้า → ระดับราคา)
- ปรับราคาเป็น % ทีเดียวทุกสินค้า: **ตั้งกำไร (%)**

**เผยแพร่/ซ่อน**
- ปุ่ม **เผยแพร่/ซ่อน** รายแถว หรือ **เผยแพร่ทั้งหมด / ซ่อนทั้งหมด** ครั้งเดียว
- สินค้าซ่อน = ลูกค้าไม่เห็น แต่ออเดอร์เก่ายังอยู่

**ตรวจสอบย้อนหลัง**
- **ประวัติเติมเงิน** — เงินเข้าทุกช่องทาง (แยก "แอดมินเพิ่มเครดิต" / "พร้อมเพย์" / "ใช้เครดิตซื้อสินค้า")
- **รายงานรายได้** — กำไรจริง (ราคาขาย − ต้นทุน) ตามช่วงเวลา
- **รายงานสต๊อก** — ขายดี / สินค้าค้างสต๊อก (ตั้ง "ไม่ขาย N วัน" ได้)
- **คลังสินค้า** — โค้ดพร้อมขายจริงต่อสินค้า (คอลัมน์ "จำนวนบัญชี")

**ความปลอดภัย**
- เปิด 2FA ทุกบัญชีแอดมิน — บังคับอยู่แล้ว
- อย่า tick "จดจำ 30 วัน" บนเครื่องสาธารณะ
- พนักงานใหม่ → สร้างที่ **เจ้าหน้าที่** และเลือกสิทธิ์ให้น้อยที่สุดที่จำเป็น
- พนักงานลาออก → **ปิดใช้งาน** ทันที (สิทธิ์หมดใน 15 วินาที)

## 9. แบบทดสอบ A–E (ตรวจสอบว่าระบบปกติ)

ใช้เวลา ~10 นาที ทดสอบครบทั้งระบบ (บนเว็บทดสอบ ใช้ dev-seed จาก §2 ก่อน):

- **A. เติมสต๊อก** — จัดการสต๊อก → วาง 2 โค้ด → แยกข้อมูล → บันทึก
  ✓ สต๊อก +2 ในตาราง / คลังสินค้าโชว์ "จำนวนบัญชี" เพิ่ม
- **B. เครดิต** — ลูกค้า → ดู → ใส่ +100 → ปรับเครดิต
  ✓ ยอดเปลี่ยน + ประวัติเติมเงินมีแถว "แอดมินปรับเครดิต"
- **C. ซื้อด้วยเครดิต** — ล็อกอินลูกค้า → ซื้อ → เลือกเครดิต → ยืนยัน
  ✓ หน้ายืนยันมีโค้ด / บัญชี→โค้ดของฉัน มีโค้ด / กระเป๋าเงินหักถูกต้อง / ออเดอร์ "สำเร็จ (wallet)"
- **D. สลิปแมนนวล** — ซื้อรอบสองแบบ PromptPay (ไม่ต้องจ่ายจริงบนเว็บทดสอบ) → แอดมินกดยืนยัน
  ✓ สถานะเปลี่ยนสำเร็จ ลูกค้าได้โค้ดที่สอง
- **E. เครดิตไม่พอ** — ปรับเครดิตเป็น 0 แล้วซื้ออีก
  ✓ ตัวเลือกเครดิตหาย / หรือขึ้น "ยอดเครดิตไม่พอ" และ QR ยังใช้ได้

ทั้ง 5 ข้อผ่าน = ระบบพร้อมขาย

## 10. ติดต่อ/แก้ปัญหา

| อาการ | ทางแก้ |
|---|---|
| ลูกค้าจ่ายแล้วไม่ได้โค้ด | ดู **คำสั่งซื้อ** — ถ้า "รอชำระเงิน" = รอแจ้งธนาคาร กดยืนยันเอง (§6) · ถ้า "รอจัดส่ง" = เติมโค้ดแล้วกด retry |
| โค้ดซ้ำ/โค้ดไม่ถูกต้อง | ค้นหาที่ **คลังสินค้า** → จัดการสต๊อก → ตรวจรายการ; ออเดอร์เก่าคืนเครดิตลูกค้าได้ที่ §4 (หัก/เพิ่ม) |
| แอดมินล็อกอินไม่ได้ (ล็อก 15 นาที) | รอ 15 นาที หรือให้ super_admin ปลดล็อกที่ **เจ้าหน้าที่** |
