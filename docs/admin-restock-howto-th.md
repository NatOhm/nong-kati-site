# วิธีใช้ฟีเจอร์ "เติมสต๊อกบัญชี" (จัดการข้อมูลบัญชี)

**สำหรับ:** พนักงานที่ดูแลสินค้าและสต๊อกโค้ด · **อัปเดต:** 5 ต.ค. 2569
**ใช้เมื่อ:** สินค้าของเราคือ "บัญชี/โค้ด" (เช่น Netflix, Spotify, HBO) — ถ้ายังไม่มีโค้ด หรือโค้ดหมด ขายต่อไม่ได้

> คู่มือหลัก: [คู่มือการใช้งานหลังบ้าน](admin-manual-th.md) หมวด 3 (เติมสต๊อกโค้ด)
> ไฟล์นี้เป็นฉบับละเอียดของฟีเจอร์เดียวกัน อ่านเมื่อทำจริงจัง ๆ หรือเจอปัญหา

---

## 1. เปิดฟีเจอร์นี้ที่ไหน

เมนู: **แคตตาล็อกและคลังสินค้า** → เลือกได้ 2 ทาง (ทำได้เหมือนกันทุกขั้นตอน)

| หน้า | URL | สิทธิ์ที่ต้องมี |
|---|---|---|
| **สินค้า** | `/management/products` | `products:read` |
| **คลังสินค้า** | `/management/inventory` | `inventory:read` |

จากนั้น ที่แถวของสินค้าที่ต้องการ ให้กดปุ่มไอคอน**รูปกล่องพัสดุที่มีเครื่องหมาย `+`**
ที่มุมขวาสุดของแถวนั้น (ปุ่มแรกในกลุ่มปุ่มด้านขวา) เอาเมาส์ชี้เหนือปุ่มจะขึ้นคำว่า **เติมสต๊อกบัญชี**
หน้าต่างที่เปิดขึ้นมีชื่อว่า **จัดการข้อมูลบัญชี - {ชื่อสินค้า}**

> เมนูหลังบ้านเปลี่ยนเป็นแบบ 7 หัวข้อเมื่อ 5 ต.ค. 2569 — ดูวิธีกางหัวข้อที่
> [คู่มือหลังบ้านหมวด 0](admin-manual-th.md#0-เมนูหลังบ้านรูปแบบใหม่-ปรับเมื่อ-5-ตค-2569) · URL ของทุกหน้ายังเหมือนเดิม

### ใครใช้ได้บ้าง

ระบบตรวจสิทธิ์ **`products:write`** ตอนกดบันทึก (ไม่ใช่ตอนเปิดหน้าต่าง) ผลคือ:

| บทบาท | ใช้ได้ | หมายเหตุ |
|---|---|---|
| Super Admin | ได้ | สิทธิ์ครบทุกอย่าง |
| Catalogue Manager | ได้ | บทบาทที่ดูแลสต๊อกโค้ดตามปกติ |
| Order Manager | ไม่ได้ | ดูแลคำสั่งซื้อ/ลูกค้า เติมสต๊อกไม่ได้ |
| Finance Viewer | ไม่ได้ | ดูยอด/รายงานอย่างเดียว |
| Support Agent | ไม่ได้ | ดูแลติ๊กต์และออเดอร์ |
| Marketing Manager | ไม่ได้ | ดูสินค้าได้ แต่เติมสต๊อกไม่ได้ |

- ถ้า**ไม่เห็นเมนู แคตตาล็อกและคลังสินค้า** แปลว่าบัญชีนั้นไม่มีสิทธิ์เข้าหน้านั้นเลย ไม่ใช่ปัญหาของฟีเจอร์นี้
- ถ้า**เห็นหน้าแต่กดบันทึกแล้วขึ้น 403** แปลว่าบัญชีนั้นเข้าหน้าได้แต่ไม่มีสิทธิ์เติมสต๊อก → แจ้งผู้ดูแลระบบ
- ทุกบทบาทในตารางนี้มาจาก `ROLE_PERMISSIONS` ในโค้ดจริง ไม่ได้เดาสุ่ม — ถ้าเปลี่ยนสิทธิ์ในโค้ด
  เกตนี้จะแดงทันที

## 2. เลือกรูปแบบข้อมูล

หน้าต่างมีตัวเลือกหลัก 2 อย่าง ใต้หัวข้อ **รูปแบบข้อมูลไอดี \***

### แบบสั้น (user:pass) — ค่าเริ่มต้น

เหมาะกับบัญชีที่ข้อความสั้น **หนึ่งบรรทัดต่อหนึ่งโค้ด** ทั้งบรรทัดคือโค้ดทั้งหมด วางได้เลยแบบนี้:

```
user01:pass1111
user02:pass2222
user03:pass3333
```

- เว้นวรรคหน้า-หลัง ระบบตัดให้เอง
- **บรรทัดว่างถูกข้าม** ไม่นับเป็นโค้ด
- ถ้าข้อมูลจากแหล่งขายมาเป็นบรรทัดเดียวยาว ๆ คั่นด้วยจุลภาค ให้**กด Enter แยกทีละบรรทัดก่อนวาง** แล้วใช้แบบสั้น

### แบบยาว (ข้อมูลหลายบรรทัด)

เหมาะกับบัญชีที่มีข้อความยาวหรือมีอีโมจิ เช่น บล็อกข้อความ HBO ที่ต้องส่งให้ลูกค้าตามต้นฉบับ

```
🍎 ➤ HBO MAX 4K  7 days 💜

✅ Mail : mansdevt@gmail.com
✅ pass : baby123456hii


✅ Mail : nextaccount@gmail.com
✅ pass : xxxxxxxx
```

กฎเดียวที่ต้องจำ:

> **เว้นวรรค (บรรทัดว่าง) 2 บรรทัดติดกัน = แยกเป็นคนละบัญชี**
> **เว้นวรรค 1 บรรทัด = ยังอยู่ในบัญชีเดิม** (เก็บไว้ให้ลูกค้าเห็นตามต้นฉบับ)

เหตุผลที่ไม่ใช่ 1 บรรทัดว่าง: แม่แบบจากแหล่งขายมักเว้นบรรทัดเพื่อให้อ่านง่ายอยู่แล้ว ถ้าตัดทุกบรรทัดว่าง
ข้อความสวย ๆ ที่ลูกค้าจะได้รับจะแตกหาย

ถ้าเผลอเว้นแค่ 1 บรรทัด ระบบจะเตือนก่อนบันทึก:

> ⚠️ ดูเหมือนมีราวๆ 8 บัญชี แต่จะถูกรวมเป็น 3 ก้อน — คั่นแต่ละบัญชีด้วยบรรทัดว่าง 2 บรรทัดติดกัน

### เรื่องตัวเลือก "ช่องทางในการแยกบัญชี / Separator"

มีปุ่มให้เลือก 3 อัน: **Comma (,) · Semicolon (;) · Tab**

- ปุ่มเหล่านี้**กดใช้ได้เฉพาะตอนเลือกแบบยาว** (เลือกแบบสั้นจะถูกปิดไว้เทา ๆ)
- **สำคัญ:** ในเวอร์ชันนี้ตัวเลือกนี้ **ยังไม่มีผลต่อการตัดข้อมูลจริง** — ระบบส่งทั้งบล็อกให้ลูกค้าตามต้นฉบับ ไม่ได้หั่นตามจุลภาค
- ถ้าข้อมูลของคุณเป็น **คู่ `บัญชี,รหัส` คั่นด้วยจุลภาคจริง ๆ** ให้ใช้ **แบบสั้น** แล้วกด Enter แยกทีละบรรทัดแทน จะได้ผลถูกต้อง

## 3. วางข้อมูลแล้วกด "แยกข้อมูล"

วางข้อความลงช่องใหญ่ **ข้อมูลไอดีและรหัสผ่าน \*** ใต้ช่องจะมีตัวเลขบอกว่า **ตอนนี้: N รายการ**
(นับตามกฎของข้อ 2 — ตัวเลขนี้ถูกนับในเบราว์เซอร์ ไม่ต้องรอเซิร์ฟเวอร์)

จากนั้นกดปุ่ม **แยกข้อมูล** (ปุ่มซ้ายล่าง) ระบบจะยัง **ไม่บันทึกอะไร** แต่จะแสดงตัวอย่างให้ตรวจก่อน:

```
จำนวนไอดีที่จะสร้าง: 3 ไอดี   (ข้ามที่ซ้ำอยู่แล้ว 2)
```

- ด้านล่างเป็นการ์ด **ไอดี #1, ไอดี #2, …** พร้อมข้อความเต็มของแต่ละบัญชี
- ถ้าสินค้ามีหลายแพ็กเกจ จะมีป้ายชื่อแพ็กเกจกำกับมุมขวาของการ์ด
- ถ้าตัวเลขเป็น **0 ไอดี** ขึ้นข้อความแดงว่า *ไม่พบบัญชีที่แยกได้ — ตรวจรูปแบบอีกครั้ง* → ยังบันทึกไม่ได้ ให้กลับไปแก้รูปแบบ

> 🔐 **ข้อควรระวัง:** การ์ดตัวอย่างแสดง **รหัสผ่านจริงเป็นตัวอักษรธรรมดา**
> อย่าแชร์หน้าจอตอนหน้าต่างนี้เปิดอยู่ และอย่าทิ้งหน้าต่างค้างไว้ข้าง ๆ เวลาลูกค้ามานั่งในร้าน

---

## 4. กด "บันทึก"

- ปุ่ม **บันทึก** จะกดได้ก็ต่อเมื่อ **แยกข้อมูลแล้ว และได้ยอดไม่เป็น 0** เท่านั้น
- กดแล้วจะขึ้นกล่องเขียว

```
เพิ่มสต๊อก 3 ไอดีเรียบร้อย (ข้ามรายการซ้ำ 2)

1 เดือน: +2
3 เดือน: +1
```

  ตัวเลขหน้าแต่ละแพ็กเกจคือจำนวนที่เพิ่มจริงในแพ็กเกจนั้น กด **เสร็จสิ้น** เพื่อปิด
- รายการในหน้า **สินค้า** จะรีเฟรชให้เองโดยไม่ต้องกดอะไรเพิ่ม

> ⚠️ **ปุ่ม "ยกเลิก" = ล้างช่องข้อมูลทิ้ง** ไม่ใช่แค่ปิดหน้าต่าง
> และถ้ากด ✕ หรือรีเฟรชหน้าเว็บ ข้อความที่วางไว้ก็หายไปทั้งหมด (ระบบไม่ได้เก็บค้างไว้)
> **ให้เก็บต้นฉบับไว้ในไฟล์/คลิปบอร์ดก่อนวางเสมอ** แล้วค่อยวางซ้ำ

## 5. สิ่งที่ระบบทำให้อัตโนมัติหลังกดบันทึก

ทุกครั้งที่บันทึก ระบบจะทำ 4 อย่างนี้เอง ไม่ต้องทำเพิ่ม:

1. **เข้ารหัสโค้ดก่อนเก็บ** — คนอื่นเปิดฐานข้อมูลอ่านข้อความดิบไม่ได้
   (เก็บทั้งข้อความเข้ารหัส และค่าแฮชไว้สำหรับเช็กซ้ำ)
2. **สต๊อก +N ทันที** ในแต่ละแพ็กเกจที่ได้รับโค้ด
3. **บันทึกประวัติการจัดสต๊อก** ชนิด **เติมสต๊อก** พร้อมยอดคงเหลือหลังบันทึก
   และบันทึกว่าใครเป็นคนกด (ดู Audit Log ได้)
4. **ข้ามโค้ดที่ซ้ำเอง** — ถ้าวางโค้ดที่มีอยู่ในระบบแล้ว หรือซ้ำกันในก้อนเดียวกัน
   ระบบจะข้ามและนับให้ว่าข้ามกี่อัน **ไม่ error และไม่ทำให้สต๊อกเพี้ยน**
   กดวางไฟล์เดิมซ้ำทุกวันก็ปลอดภัย

## 6. สินค้าที่มีหลายแพ็กเกจ (เช่น 1 เดือน / 3 เดือน)

ระบบแบ่งโค้ดให้ **วนรอบ** ให้แต่ละแพ็กเกจ เรียงตามลำดับแพ็กเกจในสินค้า
เช่น สินค้ามี 2 แพ็กเกจ วาง 10 บัญชี → แพ็กเกจแรกได้ 5 แพ็กเกจที่สองได้ 5

**ถ้าต้องการกำหนดเองว่าโค้ดไหนไปแพ็กเกจไหน** ให้ขึ้นบรรทัดด้วย **ชื่อแพ็กเกจ** ตามด้วยเครื่องหมาย `:` แล้ววางข้อมูลต่อท้าย

```
1 เดือน: user01:pass1111
1 เดือน: user02:pass2222
3 เดือน: user03:pass3333
```

- ใช้ได้ทั้งแบบสั้นและแบบยาว
- **ชื่อแพ็กเกจต้องตรงกับชื่อที่ตั้งไว้ในสินค้าเป๊ะ ๆ** พิมพ์ผิดตัว (เช่นเว้นวรรค หรือสะกดไม่ตรง) ระบบจะมองไม่เจอ
  แล้ว**แอบไปวนรอบตามปกติแบบไม่บอก** → ตรวจตัวอย่างที่ป้ายชื่อแพ็กเกจบนการ์ดทุกครั้ง
- **แพ็กเกจที่ปิดใช้งานอยู่จะถูกข้ามทั้งหมด** ระบบนับเฉพาะแพ็กเกจที่เปิดอยู่
  ถ้าสินค้านั้นไม่มีแพ็กเกจที่เปิดอยู่เลย จะขึ้นข้อความ **`NO_VARIANTS`** ในกล่องสีแดง → ให้ไปเปิดแพ็กเกจก่อนแล้วลองใหม่

## 7. ปัญหาที่พบบ่อย

| อาการ | สาเหตุ | ทำอย่างไร |
|---|---|---|
| ตัวเลขไอดีไม่ตรงกับที่คิด | วางบรรทัดว่างเปล่า ๆ ระบบนับรวมมา | ดูตัวอย่างก่อนบันทึกเสมอ |
| แบบยาวได้ 1 ก้อนแต่ควรได้หลายบัญชี | เว้นวรรคแค่ 1 บรรทัด | ต้องเว้น **2 บรรทัดติดกัน** (ระบบเตือนให้อยู่แล้ว) |
| โค้ดบางอันหายไปโดยไม่มี error | บรรทัดนั้นขึ้นต้นด้วย `ID:` `Ref:` `Order:` `Inv:` หรือ `Ref-Id:` (คำนำหน้าแบบเลขอ้างอิง) — ระบบ**ตัดทิ้งทั้งบรรทัด** | ย้ายโค้ดไปขึ้นบรรทัดใหม่ อย่าให้บรรทัดโค้ดขึ้นต้นด้วยคำเหล่านี้ |
| ได้ยอดน้อยกว่าที่วาง | เป็นโค้ดที่เคยเติมไว้แล้ว ระบบข้ามซ้ำ | ปกติ ไม่ต้องทำอะไร ดูตัวเลข "ข้ามรายการซ้ำ" |
| บันทึกไม่ได้ ปุ่มกดไม่ติด | ยังไม่ได้กด "แยกข้อมูล" หรือได้ยอด 0 ไอดี | กด "แยกข้อมูล" ก่อนเสมอ |
| กดบันทึกแล้วขึ้น 403 | บัญชีไม่มีสิทธิ์ `products:write` | ให้ Super Admin เป็นคนเติม หรือขอเพิ่มสิทธิ์ |
| ขึ้น `NO_VARIANTS` | สินค้าไม่มีแพ็กเกจที่เปิดใช้งาน | ไปที่ สินค้า → แก้ไขสินค้า → เปิดแพ็กเกจ |
| ข้อความที่วางหาย | ปิดหน้าต่าง / กดยกเลิก / รีเฟรช | เก็บต้นฉบับไว้ในไฟล์ แล้ววางใหม่ |

## 8. ข้อควรระวังเรื่องความปลอดภัย

- หน้าตัวอย่างของฟีเจอร์นี้ **แสดงรหัสผ่านจริงเป็นข้อความธรรมดา** — ห้ามถ่ายรูปหน้าจอ และอย่าแชร์หน้าจอ
- หลังบันทึก ข้อความถูกเข้ารหัสทันที แต่ถ้ายังเปิดหน้าต่างค้างอยู่ ข้อความยังอยู่บนหน้าจอ
- โค้ดที่เติมแล้วถูก **ตัดสต๊อกอัตโนมัติ** เมื่อลูกค้าจ่ายเงิน → ถ้าเผลอเติมโค้ดผิดชุด ต้องแก้ที่ Audit Log / ไม่มีปุ่มยกเลิกโค้ดในหน้านี้
- บัญชีที่เติมโค้ดคือของจริงที่ต้องส่งให้ลูกค้า อย่าทดลองใช้บัญชีส่วนตัว
- การเติมสต๊อกเป็นการ **เพิ่มเท่านั้น** ระบบไม่ตั้งยอดเป็นตัวเลขที่ต้องการ และไม่ลบโค้ดที่มีอยู่

---

## 9. เติมเสร็จแล้ว ส่งโค้ดให้ลูกค้าต่ออย่างไร

กรณีที่พบบ่อยที่สุด: ลูกค้าจ่ายเงินแล้ว แต่ออเดอร์ค้างสถานะ **รอส่งมอบ** เพราะตอนนั้นยังไม่มีโค้ด

1. เติมสต๊อกตามคู่มือนี้ให้เสร็จ
2. ไปที่ **คำสั่งซื้อและการชำระเงิน → คำสั่งซื้อ** → เปิดออเดอร์นั้น
3. กดปุ่ม **ส่งโค้ดอีกครั้ง (หลังเติมสต๊อก)** — ระบบจะตัดสต๊อกและส่งโค้ดให้ลูกค้าทันที
4. ออเดอร์จะเปลี่ยนเป็น **สำเร็จ** และลูกค้าเห็นโค้ดใน **บัญชี → โค้ดของฉัน** (`/account/codes`) ทันที

> ถ้ากดแล้วยังขึ้นว่า *โค้ดยังไม่พอ* แปลว่า**สินค้าแพ็กเกจที่ออเดอร์นี้ยังไม่มีโค้ด** ลองตรวจว่าเติมเข้าแพ็กเกจถูกตัวหรือเปล่า

## 10. ตรวจว่าเติมสำเร็จจริง

- **คลังสินค้า** → ดูคอลัมน์สต๊อก และ **ประวัติการจัดสต๊อกล่าสุด** จะเห็นแถวชนิด **เติมสต๊อก** เพิ่งเพิ่งขึ้น พร้อมยอดคงเหลือ
- **สินค้า** → คอลัมน์ **สต๊อก** ของแถวนั้นเพิ่มขึ้น N
- **Audit Log** → มีรายการของผู้กดบันทึก

ถ้าสต๊อกเพิ่ม แต่ลูกค้ายังไม่ได้โค้ด → ยังต้องทำข้อ 9 ต่อ (เติมสต๊อก ≠ ส่งโค้ด)

## สรุปใน 5 บรรทัด

1. เมนู **แคตตาล็อกและคลังสินค้า** → สินค้า หรือ คลังสินค้า → กดไอคอนกล่องพัสดุ `+` ในแถวสินค้า
2. เลือก **แบบสั้น** (1 บรรทัด = 1 บัญชี) หรือ **แบบยาว** (เว้นวรรค 2 บรรทัด = แยกบัญชี)
3. วางข้อมูล → กด **แยกข้อมูล** → ตรวจการ์ด ไอดี #1, #2 … และยอดรวม
4. กด **บันทึก** → ระบบเข้ารหัส + สต๊อก +N + ข้ามซ้ำให้เอง
5. ถ้าออเดอร์ค้างรอส่งมอบ ให้กลับไปกด **ส่งโค้ดอีกครั้ง (หลังเติมสต๊อก)** ในหน้าคำสั่งซื้อ
